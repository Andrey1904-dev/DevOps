# Архитектура локального MVP

Кабинет расширяет существующий проект, не заменяя конфигурацию ролей или Skills.
Python 3.11+ и его стандартная библиотека: HTTP-сервер, SQLite, JSON. HTML/CSS и
обычный JavaScript без сборки, CDN, npm и платных сервисов. Проверенная среда:
macOS Apple Silicon, Python 3.14.3, Node.js 26.7.0 для проверки JavaScript.

## Состав

- `academy.py`: локальный HTTP, проверки запросов, переходы состояний, SQLite,
  формирование контекста наставников. Никакого запуска пользовательского кода.
- `content.py`: 10 стартовых уроков/симуляций, 9 диагностических тем, 30 слотов
  программы, карта 9 ролей. Добавление темы не означает её прохождение.
- `web/`: интерфейс. Изменение hash показывает раздел и ничего не записывает.
- `data/academy.sqlite`: один локальный документ состояния, версия схемы 1.
  Ответы, проверки и события сохраняются атомарно с историей попыток.
- `tests/`: синтетические проверки в памяти и во временной папке внутри tests;
  основная база ученика не используется.
- `.codex/agents/`, `.agents/skills/`: существующие определения и справочники.
- `audit/mvp-verification.json`: фактические результаты технической проверки.

## Педагогический цикл

При первом запуске нет ответов, попыток или фиктивного прогресса. Диагностика
начинается только нажатием явной кнопки пользователя. Девять тем требуют
собственного ответа и перенесённого обоснования внешней проверки. Вариант
«пока не знаю» допустим. После оценки «поддержка» или «нет доказательств»
появляется уточняющий вопрос на другом материале; предыдущие попытки остаются.
Следующая непроверенная тема предлагается при общем открытии диагностики.
Алгоритм не выводит уровень из скорости ответа, уверенности или длины текста.

Шаблон программы редактируется вручную с учётом реальных наблюдений. Сохранение
не утверждает программу. Все 9 тем должны иметь проверку; затем пользователь
явно вводит `УТВЕРЖДАЮ`. Доступ к учебным попыткам открывается после этого.
После утверждения диагностический снимок закрыт от изменений. Изменение уже
утверждённого плана в интерфейсе MVP не реализовано; требуется отдельное развитие.

Состояния задания: не начато → в процессе → отправлено на проверку → требует
исправления / выполнено. Новая попытка сохраняет предыдущую. Проверяется только
последняя попытка. Подсказки открываются по одной; между первой и следующей нужна
собственная попытка. Помощь отмечается явно: самостоятельно, с подсказкой, разбор
решения, повторная проверка. Разбор готового решения не завершает задание.

Автоматическая проверка сейчас сверяет только первый путь в задании навигации.
Совпадение не завершает задание: объяснение должен проверить наставник/человек.
Остальные артефакты требуют ручной проверки по видимым критериям. Перенесённая
проверка подтверждается пользователем; её авторство технически не удостоверяется.
Принятое задание не равно устойчивому навыку: нужна новая задача на перенос.

## Наставники

Веб-приложение не подключено к модели. Выбор задания маршрутизирует подготовку
текста к профильной роли; можно выбрать любую из девяти специализаций вручную.
Контекст включает условие, критерии, попытки, помощь и этап. Текст ученика явно
обозначается как недоверенные данные; ожидаемый автоматический ответ не включается.
Просмотрите запрос, скопируйте в текущий Codex, явно разрешите нужный вызов.
Затем перенесите реальную проверку обратно в конкретную попытку.

Это ручной мост, а не автоматическая AI-интеграция. API, ключи и скрытые модельные
запросы отсутствуют. Штатные текстовые тесты ролей подтверждают вызов идентификаторов,
но не происхождение их инструкций из конкретных TOML.

## Безопасность и данные

Сервер привязан только к 127.0.0.1. Проверяются Host, Origin, сессионная cookie
SameSite=Strict/HttpOnly и CSRF-токен; CORS не включён. Статика выдаётся только
из явного списка трёх файлов. Лимит JSON — 64 КиБ. Пользовательские строки
экранируются при HTML-рендеринге. CSP запрещает внешние ресурсы и inline-скрипты.
Код не использует eval, subprocess или shell для обработки пользовательского ввода.
Имена файлов не принимаются из интерфейса. Путь основной SQLite проверяется на
симлинки. При повреждении базы автоматического сброса нет.

База не зашифрована. Это один пользователь доверенной локальной машины, не
многопользовательский сервер и не защищённое хранилище секретов. Другие процессы
этого пользователя способны читать файлы. Не открывайте порт во внешнюю сеть.
HTTP на loopback не заменяет аутентификацию для сетевого развёртывания.

Экспорт JSON содержит полное учебное состояние без сессионных токенов. Импорта
пока нет. Для полного восстановления храните отдельную копию SQLite, сделанную
при остановленном сервере; не подменяйте базу при работающем приложении.

## Ограничения и развитие

Пока нет реального терминала, Linux VM, Docker, автоматической проверки программ,
полного 30-дневного курса, внешней авторизации, импорта или редактирования уже
утверждённой программы. Сначала реальная диагностика и согласование, затем
наполнение продвинутых модулей и выбор изолированной Linux-среды отдельным решением.
Синтетические тесты не должны записываться в учебную базу. Визуальная QA отдельно
от тестов строкового рендеринга: последние не доказывают качество мобильной вёрстки.
