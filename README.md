# DevOps Academy

Персональный кабинет для старта в DevOps. Короткая теория, собственная практика,
постепенные подсказки и проверка объяснения. Ориентир — Junior DevOps, затем
DevSecOps; 30 дней по 2–4 часа не являются обещанием освоения профессии или работы.

[Открыть Academy](https://andrey1904-dev.github.io/DevOps/)

## Начать с нуля

1. Войдите в уже приглашённый аккаунт Supabase. Публичной регистрации нет.
2. На главной выберите **«Я новичок, начать с нуля»**.
3. Просмотрите 30-дневный план. Раскройте описание дней: цель, теория, практика,
   критерии и что повторить при затруднениях. Можно сохранить заметки к плану.
4. Внизу программы введите **УТВЕРЖДАЮ** и подтвердите сохранённую версию.
5. Откроется первый урок. Кнопка «Начать задание» открывает форму собственной
   попытки; сам просмотр урока ничего не засчитывает.

Диагностика для этого маршрута необязательна. Она не становится пройденной при
пропуске. Возвращаться к ней можно позже, не переписывая утверждённый план.

Если хотите оценить знания, выберите **«Проверить мои знания»**. Девять тем
проходятся добровольно, с собственными ответами и переносом реальной внешней
проверки. После этого обсуждается и утверждается адаптированный черновик.
До утверждения маршрут можно сменить: ответы, заметки и история сохраняются;
прежние варианты программы доступны в JSON-экспорте. Утверждённый план не сбрасывается.

## Материалы и ограничения

Первые пять дней наполнены: терминал и пути, файлы и каталоги, чтение журналов,
поиск, права обычных файлов. В каждом есть польза, объяснение, аналогия,
техническая основа, демонстрация с ожидаемым выводом, отдельная практика,
подсказки, критерии, разбор ошибок, итог и мини-челлендж.

Дни 6–30 — содержательные **планы**, ещё не полноценные уроки: процессы, службы,
сети, Git/GitHub, Bash, Python, контейнеры, CI/CD, логи, мониторинг, безопасность,
интеграционный проект и собеседование. Сохранены десять стабильных ID вводных
текстовых лабораторий. Наличие вводной модели не означает готовность полного дня.

В оригинальных сценариях вы исследуете журнал вымышленного игрового сервиса,
готовите копию конфигурации и разбираете доступ к технологической базе. Это не
утверждения об инфраструктуре реальных игр или фильмов. Личные профили и ответы
не входят в статические материалы, аналитические сервисы не подключены.

Стартовые лаборатории — **текстовые Linux-модели**, не настоящий терминал.
Команды не исполняются. macOS и Linux различаются; Docker, VM и реальные
лаборатории требуют отдельного согласования среды. Базовые задания открываются
последовательно по проверенным результатам; сложность нельзя повысить простым
переходом по ссылке. Подсказки открываются по одной с попыткой между ними.

Совпадение отдельного артефакта не завершает задание. Принять попытку можно только
с переносом внешней проверки и её явным подтверждением. Авторство проверяющего
технически не удостоверяется. Разбор готового решения не засчитывается как
самостоятельное выполнение. Новое задание на перенос проверяет устойчивость навыка.

Девять специализаций наставников доступны через ручной мост: подготовить текст,
просмотреть, перенести в Codex, получить проверку, вернуться и подтвердить её
сохранение. Сайт не вызывает AI и не хранит модельных ключей.

## Хранение и запуск

Онлайн: статический frontend в GitHub Pages; Supabase Auth, RLS и серверные RPC
хранят личные ответы, попытки, заметки и версии программы. В разделе «Данные и
запуск» доступен JSON-экспорт. Храните его приватно; импорт пока не реализован.

Локальная вспомогательная версия работает на Python 3.11+ со SQLite без пакетов:

    python3 -B academy.py

Открыть http://127.0.0.1:8765. Она использует отдельную локальную SQLite и не
синхронизируется с Supabase. Не открывайте Python-сервер во внешнюю сеть.
Новые хранилища начинают с нулевого прогресса; существующие данные сохраняются.

## Проверки

    python3 -B -m unittest discover -s tests -v
    node --check web/app.js
    node --check cloud/client.js
    node tests/test_frontend.cjs
    node tests/test_cloud.cjs
    python3 -B scripts/build_pages.py
    python3 -B tests/check_build.py

Браузерная проверка: `node tests/test_browser.cjs`, если уже доступны Playwright
и Google Chrome. Путь к уже установленному модулю можно передать переменной
ACADEMY_PLAYWRIGHT. Тест ничего не устанавливает, использует временный профиль
внутри игнорируемого audit/ и отдельный loopback-сервер с синтетической базой
в памяти. Это не проверка реальной пользовательской сессии Supabase.
